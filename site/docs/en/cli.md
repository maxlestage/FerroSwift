`ferroswift` translates a Rust crate into Swift files. Install it with cargo:

```sh
cargo install --git https://github.com/maxlestage/FerroSwift ferroswift-cli
```

## Commands

| Command | What it does |
| --- | --- |
| `ferroswift new <name>` | Creates an app: a Rust crate and its Swift package, then translates it. |
| `ferroswift build [crate] [-o <dir>]` | Translates `src/**/*.rs` into Swift files. |
| `ferroswift watch [crate] [-o <dir>]` | Translates, then again after every change of a Rust file. |
| `ferroswift check [crate]` | Only reports what cannot be translated; writes nothing. |
| `ferroswift file <file.rs> [-o <out>]` | Translates one file, to the standard output by default. |

`crate` is the folder of the crate (the current folder by default). `ferroswift app.rs` is short for `ferroswift file app.rs`.

## Options

| Option | |
| --- | --- |
| `-o`, `--out <dir>` | Where to write the Swift files. |
| `--no-previews` | Leaves out the `#[preview]` functions (`#Preview` needs Xcode). |
| `-h`, `--help` | Shows the help. |
| `-V`, `--version` | Shows the version. |

## Where the Swift files go

Without `-o`, `build` and `watch` write into `swift/Sources/<Name>` when the crate has a `swift/Package.swift` (the layout created by `ferroswift new`), and into `swift/` otherwise. `<Name>` is the crate's name in UpperCamelCase (`my-app` → `MyApp`).

- Each Rust file becomes one Swift file named after it: `src/views/todo_row.rs` → `TodoRow.swift`. `src/main.rs` becomes `main.swift` (its `fn main` is called at the end), `src/lib.rs` becomes `App.swift`, and a `mod.rs` takes the name of its folder.
- The files are translated together: a type, function or method declared in one file is known in the others.
- `FerroSwiftSupport.swift` holds the helpers the translation needs, when it needs some.
- A file is only rewritten when its content changes, so Xcode does not rebuild what did not change. Swift files generated earlier for Rust files that no longer exist are removed; files you wrote yourself are never touched (generated files start with `// Generated by FerroSwift`).

## Diagnostics

What cannot be translated is reported like a compiler error, with the file, the line and the column, the source line and a caret:

```text
error: not supported yet: the macro square!
  --> src/main.rs:6:20
  |
6 |     println!("{}", square!(4));
  |                    ^
```

Errors mean the Swift output is incomplete or will not compile; warnings mean it compiles but deserves a look. `build`, `check` and `file` exit with a non-zero status when there are errors, so they can run in CI. `watch` keeps running and reports each new translation.

## In a script or CI

```sh
cargo check                 # the Rust side compiles
cargo test                  # its logic is tested in Rust
ferroswift check            # everything can be translated
ferroswift build -o ios/Generated
```
